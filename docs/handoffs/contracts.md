Canonical. Roles build against THIS file, not against each other's code. If this file and `docs/brainstorm/rhea-strip-mvp-architecture.md` (the "brainstorm") disagree, this file wins. A role that needs a change reports it to the PM instead of diverging; the PM edits this file and tells every consumer.

Locked decisions D1-D14 come from the brainstorm and are final: near-sdk-rs 5.30.1 Rust contracts; SY is stNEAR itself; demo underlying is a mock `mstnear` with Meta Pool's interface; compressed demo clock `year_secs`; index = stNEAR price, scale 1e24, high-water mark; PT is its own NEP-141, YT is the vault contract itself; trading venue = offer book inside the vault, maker-priced, full fills only, no fees, no on-chain pricing math; YT listing locks the seller's ledger balance; settle is permissionless and lazy; claim/redeem only after settlement; testnet only.

Priority tags: **P0** on the demo path, **P1** credibility, **P2** only if time remains.

## 2. Accounts and units

- Network: NEAR **testnet** only. Root account `<root>.testnet` is chosen by R3's deploy script; sub-accounts: `mstnear.<root>`, `pt.<root>`, `strip.<root>` (vault and YT), `maker.<root>` (bot).
- All token amounts and the index are **U128 decimal strings on the wire, 24 decimals** (1 stNEAR = `1000000000000000000000000`). In TypeScript they are `bigint`.
- Timestamps: milliseconds, U64 decimal strings on the wire (`block_timestamp_ms`).
- `SCALE = 10^24`. PT and YT amounts are denominated in **asset (NEAR) terms**: `py = floor(sy * I / SCALE)`. "SY" = underlying stNEAR amounts.
- Demo clock: `year_secs` config (demo default `3600`: one real hour = one protocol year; real value 31536000). Mock yield and every APY label use it. UI labels it "demo clock".
- Error codes are panic strings starting with the code: `E_NOT_ACTIVE E_NOT_MATURED E_NOT_SETTLED E_STALE_INDEX E_BAD_MSG E_WRONG_TOKEN E_OFFER_GONE E_PRICE_MISMATCH E_INSUFFICIENT_YT E_MIN_AMOUNT E_TOO_MANY_OFFERS E_NOT_OWNER E_PRICE_ZERO`.
- Events: NEP-297, `"standard":"rhea_strip"`, `"version":"1.0.0"`, events `strip index_sync list fill cancel settle redeem claim withdraw`; data is a JSON array of objects with account ids and U128 strings.

## 3. Contract interfaces

### 3.1 mock-stnear (account `mstnear.<root>`, crate `contracts/mock-stnear`, owner R3)

Faithful to Meta Pool stNEAR: non-rebasing NEP-141 (decimals 24, symbol `mstNEAR`, name `Mock Staked NEAR (demo)`), NEP-145 storage registration REQUIRED for receivers (min 0.00125 NEAR), price read with `get_st_near_price`.

```text
new({ owner: AccountId, p0: U128, apr_bps: u32, year_secs: U64 })      // p0 default 1514411535945873749259456 (mirrors mainnet), apr_bps default 800, year_secs 3600
get_st_near_price() -> U128      // p0 + p0*apr_bps*elapsed_s / (10000*year_secs); elapsed since init; computed in integer math (U256); monotonic
faucet()                         // mints 100 mstNEAR (100e24) to predecessor, auto-registers predecessor, max 1000 per account total; no deposit
set_apr_bps({ apr_bps: u32 })    // owner only; settles accrued price into p0 first so price never jumps backwards
get_params() -> { owner, p0, apr_bps, year_secs, started_ms }
+ NEP-141 (ft_transfer, ft_transfer_call, ft_total_supply, ft_balance_of), NEP-145 storage_*, NEP-148 ft_metadata
```

### 3.2 pt-token (account `pt.<root>`, crate `contracts/pt-token`, owner R3)

```text
new({ minter: AccountId, name: String, symbol: String, maturity_ms: U64 })   // symbol e.g. "PT-mstNEAR-15NOV26"
mint({ account_id: AccountId, amount: U128 })     // minter only; auto-registers the account (token contract pays the 0.00125 NEAR storage from its own balance); 
burn({ amount: U128 })                            // minter only, burns the MINTER's own balance
+ NEP-141, NEP-145, NEP-148 (decimals 24)
```
The vault is the sole minter. Redeem flow: user `ft_transfer_call`s PT to the vault, the vault pays out then burns its own PT balance.

### 3.3 strip-vault (account `strip.<root>`, crate `contracts/strip-vault`, owner R1) — also the YT NEP-141

```text
new({ owner, underlying: AccountId, pt: AccountId, maturity_ms: U64, year_secs: U64, min_strip: U128 })
    // R1 as built: `pt` must be deployed AND initialised BEFORE the vault; new() reads pt.ft_metadata (YT symbol = "YT-" + PT symbol minus "PT-"), fetches the first price, and calls storage_deposit on `underlying` (0.00125 NEAR) and `pt` (0.0025 NEAR) for itself: the vault account needs about 0.004 NEAR free at init, plus storage for its wasm (~322 KB, about 3.3 NEAR) and 20+ NEAR headroom for ledger storage

// ---------- Views ----------
get_series() -> {
  underlying: AccountId, pt: AccountId, yt: AccountId /* = vault id */,
  maturity_ms: U64, year_secs: U64, min_strip: U128,
  status: "Active" | "Matured" | "Settled",        // derived from block time and maturity_index
  index: U128, index_ts_ms: U64, maturity_index: U128 | null,
  total_sy: U128, pt_supply: U128, yt_supply: U128, open_offers: u64
}
get_position({ account_id }) -> {
  yt_balance: U128, yt_locked: U128,
  yt_accrued_sy: U128,      // already settled into the ledger
  yt_pending_sy: U128,      // accrual from the account's user_index to min(index, maturity_index) (display)
  sy_credit: U128           // withdrawable sale proceeds
}
get_offers({ kind?: "Pt" | "Yt", from_index: u64, limit: u64 }) -> Offer[]      // open offers, ascending id
get_offer({ offer_id: U64 }) -> Offer | null
Offer = { id: U64, seller: AccountId, kind: "Pt" | "Yt", amount: U128, ask_sy: U128, created_ms: U64 }
// YT NEP-141 views: ft_balance_of, ft_total_supply, ft_metadata (symbol "YT-mstNEAR-15NOV26", decimals 24), storage_balance_of

// ---------- Calls (suggested attached gas; tune in sandbox, report real values to PM) ----------
sync_index()                         // 50 TGas, anyone: view-call underlying.get_st_near_price, callback stores max(stored, price)
settle()                             // 50 TGas, anyone, only at/after maturity: freezes maturity_index = max(index, fetched price); lazy and idempotent
list_yt({ amount: U128, ask_sy: U128 }) -> U64      // 30 TGas, 1 yocto; needs amount <= yt_balance - yt_locked; locks the seller's balance; returns offer id
cancel_offer({ offer_id: U64 })      // 50 TGas, 1 yocto, seller only; unlocks YT or returns escrowed PT
claim_yield()                        // 100 TGas, 1 yocto, only Settled; pays yt_accrued_sy (+ pending up to maturity_index) in underlying, zeroes the YT balance (burn) and accrual
withdraw_sy()                        // 80 TGas, 1 yocto; pays out sy_credit; on payout failure the credit is restored in the callback
sweep_residual()                     // P2, owner only, only after all PT and YT settled: withdraws vault_balance - owed

// ---------- Token receivers (ft_on_transfer; predecessor decides the path) ----------
underlying.ft_transfer_call(vault, amount, '{"action":"strip"}')                     // 300 TGas
underlying.ft_transfer_call(vault, ask_sy,  '{"action":"buy","offer_id":"7"}')       // 250 TGas; amount must equal the offer's ask_sy (overpay refunded as unused, underpay -> all unused + E_PRICE_MISMATCH logged)
pt.ft_transfer_call(vault, amount, '{"action":"redeem"}')                            // 150 TGas, only Settled
pt.ft_transfer_call(vault, amount, '{"action":"list_pt","ask_sy":"123..."}')         // 100 TGas, escrows PT, creates Pt offer
// any other predecessor token or malformed msg: return the full amount as unused (never panic in ft_on_transfer for bad input)

// ---------- YT as NEP-141 on the vault ----------
ft_transfer / ft_transfer_call / ft_balance_of / ft_total_supply / ft_metadata + NEP-145 storage_*   // ft_transfer cannot move the locked part; before maturity requires index_age <= 120 s else E_STALE_INDEX
```

Strip chain (D14): `ft_on_transfer` (strip) rejects `amount < min_strip`, returns a Promise: `underlying.get_st_near_price()` then `on_index(Strip{sender, amount})`; the callback does `index = max(index, price)`, settles the sender's YT ledger, credits YT `py = floor(amount*I/SCALE)`, `total_sy += amount`, calls `pt.mint(sender, py)` and resolves `0` unused. On any failure the full amount comes back as unused so NEP-141 refunds the user. `buy` uses the same pull-price-then-act shape. Redeem and payout paths do state updates first, then `ft_transfer`, then a callback restoring state/returning the PT on failure.

**Plan B (stored-index mode)** if the callback chain eats the schedule: index-sensitive actions require `index_age <= 120 s` (else refund + `E_STALE_INDEX`), and SDK/keeper call `sync_index` first. Same interfaces. R1 decides at the end of its phase 2 and reports to the PM.

### 3.4 Yield accounting (integer form, U256 for every mul-div)

```
index        = max(stored_index, fetched_price)                  // never decreases; fetched_price == 0 -> E_PRICE_ZERO
strip:       py = floor(sy_in * I / SCALE)                        // mint py PT and py YT
interest:    accrued_sy += floor(yt_bal * SCALE * (I_cur - I_prev) / (I_prev * I_cur))
             first touch (user_index == 0): user_index = I_cur, accrue 0
             settle BEFORE any YT balance change, for both parties
cap:         I_cur = min(index, maturity_index) once settled
settle():    once, at/after maturity: maturity_index = max(index, fetched_price)
redeem PT:   sy_out = floor(pt_amt * SCALE / maturity_index)      // after settle
claim YT:    pay accrued_sy (including pending to maturity_index), burn YT balance
rounding:    every payout floors (vault's favour)
```
Invariants (property-test them): `pt_supply == yt_supply` before maturity; `vault_sy_balance >= pt_supply*SCALE/I + sum(unclaimed_accrued)`; index never decreases. Do not derive accounting from `ft_balance_of(vault)` (donation attack); use internal counters. Worked vector: strip 100 stNEAR at I=1.5 gives 150 PT + 150 YT; index to 1.6 gives YT accrual 150*(1/1.5 - 1/1.6) = 6.25 stNEAR; vault retains 93.75 stNEAR * 1.6 = 150 NEAR = PT supply.

### 3.5 Phases

`Active` (`now < maturity_ms`): strip, list/cancel/buy, YT transfer, views. `Matured` (`now >= maturity_ms`, not settled): `settle()`, cancel only; strip/buy/list revert or refund `E_NOT_ACTIVE`. `Settled` (`maturity_index` set): PT redeem, YT claim, withdraw_sy, cancel.

### 3.6 Offer-book rules

At most 5 open offers per account (vault pays storage). Full fills only. Seller proceeds go to `sy_credit[seller]` (pull payment via `withdraw_sy`), so a seller unregistered on the underlying cannot block a fill. YT offer lock: `yt_locked += amount`; fill does `move_locked_yt(from,to,amt,idx)` which settles both ledgers at the fresh index first, so the seller keeps interest accrued before the fill. PT offer: PT arrives via `list_pt`, escrowed; fill pays the buyer with `pt.ft_transfer`; on failure the buyer's stNEAR is refunded as unused and the offer stays. Offers cannot be created at/after maturity.

Internal Rust seam inside `strip-vault` (R1 owns `lib.rs`, `ledger.rs`, `series.rs`; the same R1 agent writes `market.rs` after ledger): `lock_yt`, `unlock_yt`, `move_locked_yt`, `credit_sy`, `require_active`; `market.rs`: `create_yt_offer`, `create_pt_offer`, `cancel_offer`, `fill_offer`, `get_offers`.

### 3.7 R1 as-built deviations (accepted by the PM, authoritative over 3.3 where they differ)
- YT NEP-145: registration deposit is REQUIRED, min = max = 0.00125 NEAR, kept by the vault. Strip and buy auto-create the receiver's ledger entry at the vault's cost; `ft_transfer` to an unregistered YT receiver panics. The SDK planner keeps batching `storage_deposit` on the vault for YT receivers.
- Return values: `settle` -> maturity index (U128); `sync_index` -> stored index; `list_yt` -> offer id (ids start at 1); `cancel_offer` -> bool; `claim_yield` -> paid amount and auto-cancels the caller's open YT offers.
- YT `ft_transfer` in `Matured` (not yet Settled) is refused with `E_NOT_SETTLED`.
- Extra error codes: `E_MATH E_STORAGE_LOW E_NOT_REGISTERED`; log-only: `E_PAYOUT_FAILED E_MINT_FAILED E_PT_TRANSFER_FAILED E_SWEEP_FAILED E_PRICE_FETCH_FAILED`. `E_STORAGE_LOW`: vault storage headroom below 0.02 NEAR (checked before strip mint and PT buy).
- Measured gas (burnt, TGas): strip 15.1 (attach 100; refunds cleanly at 60 or less), buy 11.6-12.3 (attach 80+), list_pt 6.9 (40), redeem 13.0 (70), list_yt 2.8 (20), cancel 2.8/7.1 (30/40), sync_index 6.0 (attach 50; fails at 20), settle 6.1 (40), claim_yield 7.0 (50), withdraw_sy 6.7 (50), sweep_residual 10.4 (80). Safe attach values for the planner: strip 150, buy 150, redeem 100, list_pt 60, list_yt 30, cancel 50, sync_index 50, settle 50, claim_yield 80, withdraw_sy 80 (the real Meta Pool price view is heavier than the mock).
- R3 as-built, accepted: `withdraw_sy` with zero credit panics `E_MIN_AMOUNT`; mock faucet cap panics `E_FAUCET_CAP`; PT/YT symbols use `DDMMMYYYY` (e.g. `PT-mstNEAR-15NOV2026`); `claim_yield` with part of the YT locked pays/burns only the unlocked part (R1 auto-cancels the caller's YT offers first); registration and the main call share one `TxStep` (one wallet batch, no separate register step); `pt-token` extra views `get_minter`, `get_maturity_ms`; mock `get_faucet_minted`; `FakeClient` extras `chain.advance(ms)`, `chain.advanceToMaturity()`, `asFakeClient`. `getMode()` defaults to `testnet` once `deployed: true`; `pnpm dev` forces fake.
- SDK `position().ytPendingSy` is computed against min(liveIndex, maturityIndex ?? liveIndex) (display only; payouts are unchanged). Frontend previews and accrual must use `series.liveIndex`, not `series.index`.
- Build note: `cargo near build non-reproducible-wasm` must run with `PATH=$HOME/.cargo/bin:$PATH` (rustup cargo has the wasm32 target; /usr/bin/cargo does not).

## 4. Pricing (TypeScript SDK only; floats fine)

`r` implied APY (annual effective), `τ = max(0, maturity_ms - now_ms) / 1000 / year_secs`, `I` = price / 1e24.

```
pPT(r) = (1 + r)^(-τ)          pYT(r) = 1 - pPT(r)          // NEAR per 1 PT / 1 YT, pPT + pYT = 1
ask_sy(YT a asset-units) = a * pYT(r) / I      ask_sy(PT a) = a * pPT(r) / I
implied r from ask:  YT: pPT = 1 - ask_asset/a ; r = pPT^(-1/τ) - 1
fair YT price (given underlying APY u):  (1+u)^τ - 1
buyer break-even underlying APY = pYT / τ ;  YT leverage = 1/pYT ;  PT fixed return = 1/pPT - 1
underlying APY = (I_now / I_then)^(year/elapsed) - 1  (mock: derived from apr_bps; mainnet reference: 365-day sample)
accrued YT yield (portfolio) = ytBal * (1/I_user - 1/I_now) stNEAR
```
Worked check: r=8%, τ=0.5, I=1.5144: pPT=0.9623, pYT=0.0377, listing 100 YT asks about 2.49 stNEAR. Display vocabulary: Market, Maturity, Underlying APY, Implied APY, Fixed APY, Long Yield APY (estimate), PT Discount, YT Leverage, Mint/Redeem, Buy/Sell PT/YT, Claim yield, **Sell future yield** (flagship), names `PT-mstNEAR-<DDMMMYYYY>` (see `docs/research/03-protocol-prior-art.md` R2, R3).
